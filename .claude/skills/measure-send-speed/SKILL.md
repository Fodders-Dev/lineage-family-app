# Замер скорости отправки

Протокол честного замера — `docs/speed_measurement.md`. Скрипт создаёт два
одноразовых аккаунта, директ-чат, шлёт N сообщений последовательно и удаляет
аккаунты.

## 1. Клиентская сторона (с этой машины)

```bash
node tool/measure_send_speed.mjs
```

Выводит p50/p95/min/max send-to-ack. С 31.08.2026 сервер в РФ (HOSTKEY):
RTT ≈ 20–30мс входит в цифры (раньше РФ→NL было 40–60мс).

## 2. Серверная разбивка (те же отправки)

```bash
ssh fodders "journalctl -u rodnya-backend --since '10 minutes ago' --no-pager | grep -E 'send-timing.*ack=' | tail -25"
```

## Интерпретация (базлайны)

| метрика | до SPEED-6 | NL, после SPEED-6 | РФ, после push-фикса (31.08) | тревога если |
|---|---|---|---|---|
| client p50 | 1533мс | 74мс | **43мс** | > 300мс |
| client p95 | 2031мс | 250мс | **64мс** | > 300мс |
| server access | 150–430мс | 1–3мс | 2–3мс | стабильно > 50мс |
| server persist | 670–1720мс | 7–15мс | 12–18мс | стабильно > 100мс |
| server fanout (max) | 7400мс | ~530мс | **57мс** | > 200мс |

- SPEED-7 (30.08) вынес notifications/pushDeliveries из блоба в таблицы —
  фан-аут теперь INSERT, а не блоб-RMW. Стабильные всплески persist под
  бёрстом — повод смотреть pg-индексы таблиц / нагрузку VPS, а не блоб.
- Рост persist с историей чата = деградация индексов таблиц — смотреть план
  запроса, НЕ возвращать сообщения в блоб.
- `fanout=` в логе идёт ПОСЛЕ ack и юзера не задерживает.
